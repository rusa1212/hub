
> 기준: 음성 입력 → AI → 음성 출력 파이프라인 완성 이후  
> 목표: AI 페르소나 강화 · UI/UX 개선 · 목소리 선택 구현

---

## 1. AI 페르소나 강화

### 1-1. 캐릭터 아크 부여
- 단순 도우미가 아닌 **"음악을 깊이 아는 친구"** 포지셔닝
- 음악/콘텐츠 추천 시 상황에 맞는 말투 사용
  - 예: "이건 집중해야 할 때 딱이야", "오늘 피곤해 보이는데 이거 한번 들어봐"
- system instruction에 캐릭터 배경, 말투 규칙, 금지어 명시

### 1-2. 상황 인식 응답
- 사용자가 맥락을 언급하면 톤·내용 자동 조정
  - `공부 중` → 집중에 도움되는 추천, 짧고 방해 없는 응답
  - `운동 중` → 에너지 높은 톤, 빠른 템포 콘텐츠 추천
  - `자기 전` → 차분하고 낮은 톤, 수면 유도 콘텐츠
- system instruction에 상황별 응답 가이드라인 추가

### 1-3. 응답 길이 제약
- 화면 없이 듣는 앱 특성상 **2~3문장 이내** 응답 강제
- system instruction에 명시: "항상 핵심만, 길게 늘어지지 않게"
- 필요 시 후속 질문으로 대화 이어가는 방식 유도

## 2. UI/UX 개선

### 2-1. 실시간 오디오 파형 시각화
- 녹음 중 Web Audio API(`AnalyserNode`)로 실시간 waveform 표시
- 현재 펄스 애니메이션 대체 → 실제 음성 입력 시각적 피드백
- 구현 위치: `AirPodsLog.jsx` + `audioUtils.js`

### 2-2. TTS 재생 중 애니메이션
- 에이전트 응답 재생 중 **골드 링 / 파동 확산 효과** 표시
- "에이전트가 말하고 있다"는 시각적 상태 명확화
- CSS animation 또는 Canvas 기반 구현

### 2-3. 레이아웃 재구성 — 음성 중심
- 텍스트 채팅 버블을 보조 요소로 전환 (기본 접힘 또는 작게 표시)
- **음성 상태 표시 영역**이 화면 중심을 차지하도록 재배치
- 음성 앱 컨셉에 맞는 UI 계층 정리

### 2-4. 온보딩 흐름
- 첫 접속 / 세션 생성 시 에이전트 음성 인사 자동 재생
  - 예: "안녕, 나는 ○○야. 뭐 도와줄까?"
- `createSession` 완료 후 TTS 인트로 호출 추가
- 신규 사용자 경험 진입점 개선

## 3. 목소리 선택

### 3-1. 보이스 미리듣기
- 각 보이스로 샘플 문장을 TTS 재생 후 선택하는 UI
- 선택 전 실제 목소리 확인 가능
- 구현: 보이스 선택 패널 + `/api/tts` 샘플 요청

### 3-2. 페르소나 연결
- 보이스마다 캐릭터 이미지·이름·설명 부여
- 예시:

| 보이스 ID | 캐릭터명 | 설명 |
|-----------|----------|------|
| Kore | 차분한 연구자 | 조용하고 신뢰감 있는 목소리 |
| Puck | 에너지 넘치는 친구 | 밝고 빠른 템포 |
| Charon | 감성적인 DJ | 낮고 무드 있는 목소리 |

- `backend/.env`의 `GEMINI_TTS_VOICE` 동적 교체로 연동

### 3-3. 설정 저장
- 선택한 보이스를 세션 또는 로컬스토리지에 유지
- 재접속 시에도 마지막 선택 보이스 유지
